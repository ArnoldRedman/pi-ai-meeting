# 多模型会议

## 何时用 / 何时不用

**用**：判断题要多视角；我已有判断想被反驳；有 3–5 个互斥方案要选一个；稿件改了几轮需要"验收"（有没有引入新矛盾）；需要机制层面的挑错。

**不用**：事实查询（用 `web_search`）、代码实现（直接做）、只有一个合理答案的问题、需要真实读者数据的问题。

## 席位

先读 `C:\Users\zhuzi\.pi\agent\models.json`（`providers → models` + 各模型的 `thinkingLevelMap`）。**档位只能选模型自己支持的档**，不支持的档位会直接失败。

默认四席（实测特征，用来决定"谁的意见该多信一点"）：

| 席位 | model | 档位 | 实测特点 |
|---|---|---|---|
| sol | `zhuzi/gpt-6.1-sol` | medium | 文本质量最好、结构最清；**保守，极少主动改判** |
| astra | `zhuzi/gpt-6-astra` | medium | 同 sol，但对"前提是否成立"更敏感 |
| grok | `zhuzi/grok-4.7` | xhigh | **最敢改判**；擅长抓机制漏洞；静默思考期最长（60–140 秒无输出是正常） |
| ds | `zhuzi/deepseek/deepseek-flash` | high | 输出最长、机制推演最狠；**常忽略形式约束**（诗、字数、格式一律要单独盯） |

## 三条硬规矩（违反必出事）

1. **换／加模型后，先让用户在 pi 里按一次 `/model` 重载注册表**。否则该席位 0 秒硬失败：`Unknown subagent model '...' in the active Pi model registry`。
2. **第二轮必须并行**（`runs.all`）；**每一轮都要给 `timeoutMs`**；**单席位失败不许带崩整场**（per-promise `catch` + 降级 fallback）。
3. **不许下"精确字数"约束**——实测 grok 会起 `bash` + `python` 数字数，拖慢整场。写成"控制在 N 字左右，**不必精确，不要为此运行命令**"。

## 流程

1. **写问题单**（模板见 `references/question-design.md`）：逼具体、给**机制契约**、允许它们反驳我、**允许它们自己写一版（选项 D）**。
2. **第一轮：并行独立表态**。同题、互相隔离（`context: "fresh"`）。返回值里**必须带上 `runId`**，第二轮要用。
3. **门控**：只有出现**实质分歧**才开第二轮；措辞差异不开。多数一致时直接给用户结论，省 4 次调用。
4. **第二轮：匿名交叉质询**。用 `resume: <第一轮 runId>` + 只喂**别家的答案**，**不标是谁**（避免"是我提的我就坚持"）。要求新 key（`<seat>-r2`）。
5. **投票轮**（有互斥方案时）：每人一票 + 一行理由 + **一句"如果我这票是少数，我接受哪个"**——这一句能免掉一整轮 Delphi。
6. **汇总**：产出分三类——**真洞 / 我已知的取舍 / 空话**；**逐条自己回读原文验证**（不要当传声筒）；把"谁改了什么主意"单独列出来（那是最有信号的部分）。
